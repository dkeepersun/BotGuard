# 题型目录与第三期选型

状态：**第三期已实现**。日期：2026-10-21。前置文档：`docs/challenge-types.md`（滑块）、`docs/click-challenges.md`（点选）、`docs/rotate-challenge.md`（旋转）。

## 1. 调研来源

- **国内厂商的常见题型**：滑动拼图、文字点选、图标点选、语序点选、空间推理、推理拼图（交换两块）、九宫格、旋转。例如天翼云边缘安全支持“滑动拼图、文字点选、图形点选、VTT 空间语义”四种（[天翼云文档](https://ctyun.cn/document/10065985/10580095)）；行业资料对语序点选、空间推理的定义见 [阿里云开发者社区](https://developer.aliyun.com/article/1173230)。打码工具方面，点选、九宫格、空间推理被列为本地识别不稳定、需要走付费打码的题型（[少数派](https://sspai.com/post/97573)）。
- **研究结果**：
  - Open CaptchaWorld（NeurIPS 2025，[论文](https://arxiv.org/html/2505.24878)）测了 20 类题型。最强的智能体（Browser-Use + o3）总成功率 40%，人类 93.3%。o3 至少解出过一题的类型有：旋转匹配、图像识别、图像匹配、区域选择、飞镖计数、物体匹配、选动物；计数类（Dice_Count）、按顺序点击（Click_Order）、放点（Place_Dot）、路径（Path_Finder）都没有解出。
  - COGNITION（2025）的结论已写在 `docs/click-challenges.md`：大模型擅长“认出东西”，不擅长精确定位和数数。

| 滑动拼图 | 几乎所有厂商 | 拖动 | 找缺口位置 | 已有 `slider` |
| 旋转对齐 | 极验、Arkose | 拖动 | 圆盘与外圈对齐 | 已有 `rotate` |

| 图形计数点选 | 研究推荐 | 按序点击 | 数点数、数边数 | 已有 `click_shape` |
| **推理拼图（交换两块）** | 易盾、极验 | 拖动交换 | 找出两块错位的图块 | **第三期 `jigsaw`** |
| **图标点选** | 极验、易盾、腾讯 | 按序点击 | 按提示图标找出变形后的同款 | **第三期 `click_icon`** |
| **语序点选** | 极验、易盾、KgCaptcha | 按序点击 | 自己判断成语顺序（提示里不给顺序）再定位 | **第三期 `click_order`** |

| 计数选择（选数字） | 研究题 | 选项 | 计数 | 不单独做：选择题可以盲猜，计数已经放进图形点选 |
| 连线 / 走迷宫 | 研究题 | 拖动 | 路径推理 | 暂缓：手机上操作繁琐，误判率高 |
| 长按按钮 | Arkose、PerimeterX | 长按 | 行为节律 | 不做：脚本很容易模拟，无障碍体验差 |
| 短信上行 / 语音 | 易盾 | 发短信 | 手机号成本 | 不做：需要运营商通道，超出自建服务范围 |

## 3. 第三期四个新题型

所有题型都由程序生成，不依赖图片素材，避免版权和题库泄露的问题；答案都加密封存在签名 challenge 中，服务端无状态。

### 3.1 推理拼图 `jigsaw`

- 画面 320×200，切成 2 行 × 4 列共 8 块，随机交换其中两块。画面上有贯穿各块边界的色带和色块，错位的两块会让线条断开。
- 用户把一块拖到另一块上，两块互换。答案是这两块的编号（不分先后）和拖动轨迹。
- 校验：两块必须正确；轨迹从被拖的块内开始、在目标块内结束；拖动时长、点数、瞬移、匀速、等间隔规则与滑块一致。盲猜成功率 1/28。

### 3.2 图标点选 `click_icon`

- 提示是一条图标小图，例如“☁ ⚡ ♥”，要求按顺序点击大图中的同款图标。
- 大图中的图标经过随机旋转、缩放、换色，并混入其他图标作为干扰，所以模板匹配不能直接命中。
- 共 14 种程序绘制的图标：心、星、月、闪电、云、房子、水滴、箭头、十字、钥匙、雨伞、旗帜、叶子、圆环。

### 3.3 语序点选 `click_order`

- 图中散布一个四字成语的四个字，再加 1–2 个干扰字。提示只说“请按成语的正确顺序点击文字”，不给出顺序。
- 复用文字点选的字形图集和扰动方式；图集里补入成语用到的字，用 `tools/glyphatlas` 重新生成。

### 3.4 空间推理 `spatial`

- 图中按松散网格摆放带颜色的图形。提示例如“依次点击：红色圆形右边的图形、蓝色三角形上方的图形”，要求点的是被描述物体旁边的那个，而不是被描述的物体本身。
- 生成时保证答案唯一：被描述的物体按“颜色 + 形状”是唯一的，所指方向上紧邻的格子里恰好有一个图形。

## 4. 难度排序与配置

自适应模式在高风险时出列表中最难的题型。排序从易到难：

`slider` < `rotate` < `jigsaw` < `click_text` < `click_order` < `click_icon` < `click_shape` < `spatial`

- 新建 action 默认包含全部 8 种交互题型；已有 action 不会自动加入新题型，需要在后台勾选。
- 题型列表的字段从 64 字符放宽到 255 字符（迁移 0006），8 种题型名连起来超过了 64 字符。

## 5. 局限

- 推理拼图：可以穷举 28 种交换组合，按“边缘接缝是否连续”打分来求解，与旋转题的局限同类。
- 图标点选、语序点选：专门训练过的检测模型可以识别。
- 空间推理：对通用大模型较难，但需要用户读懂一句描述，比点击类题目略慢。

所有题型都只是随机出题池中的一种，要配合风险分层、PoW 和限流一起使用。

## 6. 背景图（2026-10-28）

所有题型共用 `internal/service/imagegen` 的背景。原来的背景结构固定：两色渐变总是从左上到右下，上面叠 10–16 个半透明圆、矩形、三角形，再加均匀噪声。现在每张图随机组合以下几层，层的种类、数量、参数都随机：

| 层 | 做法 |
|---|---|
| 底色 | 任意角度的 2–3 段线性渐变、随机圆心的径向渐变、四角双线性混色，三选一 |
| 纹理 | 两层值噪声（fBm）：一层调亮度，一层向第三种颜色染色，尺度随机 |
| 图案 | 1–2 层淡的条纹、同心波纹、波浪线或网格，角度和周期随机 |
| 几何 | 8–14 个半透明的圆、旋转矩形、三角形、多边形、圆环，部分带渐隐 |
| 曲线 | 3–6 条细贝塞尔曲线 |
| 调色、颗粒 | 每个通道随机增益和 gamma（偏色），颗粒强度随机，三分之一的图是彩色颗粒 |

点选类（文字、语序、图标、图形、空间推理）另外加两步：

- **干扰笔画**（`imagegen.Clutter`，在题目元素之前画）：6–11 段短弧、钩形和 1–2 条长曲线，颜色与题目元素同类：文字题用深色，图形和图标题用鲜艳色。原来背景提亮后整体偏浅，题目元素是图中唯一的深色或高饱和区域，一个亮度或饱和度阈值就能把它们切出来交给 OCR 或模板匹配。干扰笔画都是开放的线条，不是字也不是封闭图形，真人一眼能分开。
- **成图扰动**（`imagegen.Finish`，在题目元素之后画）：1–2 条贯穿全图的淡细线、轻微偏色（每通道 ±5% 增益、±5 亮度）和颗粒。题目元素的颜色不再等于固定的调色板值，填充区域也不再是纯色。

滑块、旋转、推理拼图只换了背景，没有加这两步：干扰线会跨过缺口、圆盘边缘和图块接缝，反而给出“连续”的假线索，干扰真人判断。

### 实测

Apple M4 Pro，`go test -bench`，与改动前（main）对比：

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 单张背景耗时 | 0.95 ms | 2.7 ms |
| 整题生成耗时（滑块 / 文字点选 / 图形点选） | 1.9 / 3.6 / 2.3 ms | 3.3 / 5.9 / 4.6 ms |
| JPEG 大小（base64，点选题 / 滑块背景） | 11–13 KB / 17 KB | 13–14 KB / 16 KB |
| 文字点选：远离文字的深色连通区域（亮度 < 110、≥ 12 像素，即二值化后 OCR 要排除的候选） | 每张 3.8 个 | 每张 10.8 个 |
| 空间推理：目标像素与固定调色板颜色相差 ±8 以内的比例（按颜色查表找目标） | 85.7% | 45.7% |
| 滑块：按缺口轮廓边缘强度找位置的求解器，第一名命中 / 前两名命中 | 37.7% / 100% | 42.7% / 100% |

- 耗时增加约 1.5–2.5 ms，仍在预生成题库（`PuzzlePool`）和并发上限能吸收的范围内；图片大小基本不变，因为新增的层大多是低频的。
- 滑块的数字说明背景对滑块帮助不大：假缺口才是主要防线，求解器总能找到真假两个缺口，再二选一。
- 没有做 OCR 和多模态模型的实测（本机没有 OCR 引擎），上面的连通区域数只是 OCR 前处理难度的代理指标。
