# 第二期设计：点选验证（文字点选、图形计数点选）与随机出题

状态：**已实现**（实现记录见第 12 节）。日期：2026-10-20。前置：第一期 `docs/challenge-types.md` 已实现。

## 1. 背景

第一期只有一种交互题型（滑块），而演示已经证明：脚本用 canvas 几毫秒就能找到缺口，配上仿人轨迹就能通过。单一题型容易被针对性优化。

研究数据（COGNITION，2025 年 12 月，7 个多模态大模型、18 类题型，[论文](https://arxiv.org/html/2512.02318v2)）：

| 难度档 | 题型 | AI 通过率 |
|---|---|---|
| 已被攻破 | 图片识别、选动物、图片匹配、路径寻找等 | 超过 40%，部分平均超过 60% |
| 难 | **按顺序点击**、**数骰子点数**、选图块、点选区域、在指定位置打点 | 低于 20%；给 GPT-5 几个例题后，按顺序点击为 25%，其余为 0% |
| 快被攻破 | 旋转对齐 | 低于 20%；给例题后为 50% |

论文的规律是：**大模型擅长“认出东西”，不擅长“精确定位”和“数数”**。建议在图上连续空间内精确点击、加入计数、把多个难点组合进同一道题。

## 2. 目标与非目标

目标：

1. **点选框架**：服务端出图和提示，用户按顺序点击，服务端按坐标容差、点击顺序和点击行为校验。答案仍加密放进签名 challenge，服务端无状态，业务方 SDK 不变。
2. **文字点选**（`click_text`）：例如“请依次点击：春 风 得 意”。用户最熟悉。
3. **图形计数点选**（`click_shape`）：例如“依次点击：有 5 个点的方块 → 六边形 → 红色的三角形”，把精确定位、计数、顺序三个难点组合在一起。
4. **随机出题**：每个 action 配置允许的题型列表；中等风险从列表随机选，高风险固定选列表中最难的题型。

非目标：

- 不宣称能防住 AI。文字点选已有专门的识别工具和付费打码服务；图形计数点选目前对通用大模型最难，但针对性训练的检测模型同样可以攻破它。
- 旋转题、语序（成语）点选留到以后。
- 点选题没有无障碍方案，视障用户继续走第一期的备用路径（fallback）。

## 3. 题型、模式与选题

题型（kind）：`invisible`、`slider`、`click_text`、`click_shape`、`fallback`。

action 配置改为“模式 + 题型列表”：

| 模式 | 出题方式 |
|---|---|
| `invisible` | 只有后台 PoW（不变） |
| `interactive` | 每次从题型列表中随机选一种交互题 |
| `adaptive` | 低风险：invisible；中风险：从列表随机；高风险：列表中最难的题型，并且 PoW ×4 |

- 难度排序：`click_shape` > `click_text` > `slider`。
- 第一期的 `slider` 模式迁移为 `interactive` + 列表 `[slider]`，行为不变。命令行仍接受 `-mode slider`，作为它的别名。
- 新建 action 的默认值：模式 `adaptive`，列表为全部三种交互题型。

迁移 0004：

```sql
ALTER TABLE botguard_app_action ADD COLUMN challenge_kinds VARCHAR(64) NOT NULL DEFAULT 'slider' AFTER challenge_mode;
UPDATE botguard_app_action SET challenge_mode = 'interactive' WHERE challenge_mode = 'slider';
```

命令行：`botguard-ctl action set -app app_xxx -action login -mode adaptive -kinds slider,click_text,click_shape`。

## 4. 协议（全部新增，向后兼容）

签发响应中，点选题带 `click` 对象：

```json
{
  "kind": "click_shape",
  "click": {
    "width": 320, "height": 200,
    "image": "data:image/jpeg;base64,...",
    "prompt": "请依次点击：有 5 个点的方块、六边形、红色的三角形",
    "targets": 3
  }
}
```

- 提示文字以纯文本返回，不做成图片。机器人读懂提示并不难，难点在找准位置和数清数量；而纯文本可以被读屏软件读出、方便调试。
- 正确答案（每个目标的圆心和半径）放在签名 challenge 的加密字段里。

solve 请求的 `answer` 增加点选格式：

```json
{"clicks": [[1830, 152.5, 98.0], [2410, 61.0, 140.5], [3020, 240.0, 37.5]], "moves_between": [14, 9, 11]}
```

- `clicks` 每项为 `[自面板显示起的毫秒数, x, y]`，x、y 是原图坐标；
- `moves_between[i]` 是第 i 次点击前的指针移动次数；
- 失败仍统一返回 422 `ANSWER_INVALID`。

## 5. 校验规则

1. **数量**：点击数必须等于目标数（3–4 个）。
2. **位置与顺序**：第 i 次点击必须落在第 i 个目标的圆内。半径 = 目标半径 + 4 像素，文字约 18–22 像素，图形约 16–28 像素。
3. **时间**：
   - 第一次点击距面板出现至少 400 毫秒（要读题）；
   - 相邻两次点击至少隔 150 毫秒；
   - 全程不超过 60 秒；
   - 3 次以上的点击间隔不能完全相等（相差在 15 毫秒内视为相等）。
4. **移动**：鼠标操作时，每两次点击之间至少要有 2 次指针移动，没有移动的“瞬移点击”判为脚本。触屏不检查这一条。

和滑块一样，这些行为规则只能挡住粗糙的脚本。

## 6. 出图

### 6.1 公共部分

第一期滑块的程序化背景（随机多边形、渐变、噪声）抽到公共包 `internal/service/imagegen`，滑块和两种点选共用。图片尺寸 320×200，JPEG 质量随机 60–80。

### 6.2 文字点选

- **字形图集**：开发时用 `go run ./tools/glyphatlas`，从思源黑体 / Noto Sans SC 把约 300 个常用字画成一张灰度图集，连同坐标表一起提交到 `internal/service/clicktext/assets/`。运行时只读图集，不需要字体文件。
  - 字体文件放在 `third_party/fonts/`，已加入 `.gitignore`，不提交。
  - 仓库提交 SIL OFL 1.1 许可全文和来源说明。OFL 允许嵌入和生成衍生位图。
  - 生成工具新增依赖 `golang.org/x/image`（Go 官方扩展库），只有这个工具用到，gateway 运行时不依赖它。
- **字表**：剔除形近字（如 己/已/巳、土/士、未/末、人/入、日/曰、大/太/犬），避免真人也分不清。
- **出图**：
  - 随机选 3–4 个目标字和 1–2 个干扰字，散布在图上，互不重叠；
  - 每个字随机旋转 ±35°、字号 26–34 像素、随机颜色（与背景保持足够对比度）、轻微倾斜；
  - 再叠加干扰线和噪点。

### 6.3 图形计数点选

- 程序绘制 7–9 个图形：
  - 正多边形（3–6 条边）；
  - 圆；
  - 星形；
  - 带 1–6 个点的“骰子”方块。
- 每个图形的颜色从 5 种可命名的颜色中选（红、蓝、绿、黄、紫），大小分两档，位置随机，允许少量重叠以增加杂乱度。
- **目标描述**由“形状 / 边数 / 点数 / 颜色 / 大小”组合而成，例如：
  - “有 4 个点的方块”；
  - “五边形”；
  - “最小的圆”；
  - “蓝色的三角形”。
- **唯一性**：生成后逐条检查每个描述在图中是否恰好对应一个图形，不唯一就重新生成。
- **干扰**：
  - 刻意放入相近的干扰项，如 4 点和 5 点的骰子、五边形和六边形；
  - 同色异形、同形异色；
  - 这些设计是为了让模型必须真的数清楚。

### 6.4 性能

两种出图都用 Go 标准库（`image/draw`，旋转用双线性插值）。目标是单张 5 毫秒以内，实现后用 benchmark 实测。并发上限沿用第一期的做法。

## 7. 前端组件

- 新增点选面板：题目文字、图片、已点击位置的序号标记，以及“重置”“换一张”“无法完成？”三个按钮。点满目标数后自动提交。
- 记录点击时间、坐标和点击之间的指针移动次数；坐标按显示缩放换算回原图坐标。
- 失败时提示“点击位置或顺序不正确”，并自动换题。连续失败 3 次后冷却 10 秒，与滑块一致。
- 键盘用户：点选题无法用键盘完成，面板上的“无法完成？”进入备用路径，与第一期相同。

## 12. 实现记录

- **性能**（Apple M4 Pro，`go test -bench . ./internal/service/...`）：图形点选单张约 2.4 毫秒，文字点选约 3.8 毫秒，都低于 5 毫秒，沿用并发上限，不做题库。
- **字形图集**：从 Noto Sans SC Regular 生成 336 个字（手写字表时出现了 7 个重复字，已去重，并由测试防止再次出现），图集 PNG 约 235 KB，嵌入 gateway。字体文件只在 `third_party/fonts/`，不提交。新增依赖 `golang.org/x/image`，只有生成工具使用。
- **骰子可读性**：浏览器实测发现小号骰子的点只有约 2 像素，人眼难以数清。改为骰子一律画成大号（骰子本来就没有“大小”描述），点的半径不少于 3 像素。
- **浏览器实测**（内置浏览器，由我操作）：
  - 文字点选：按顺序点 4 个字通过，业务端看到 `click_text / low`；
  - 图形点选：数清点数后点 3 个图形通过；
  - “脚本随机点击图形题”被拒，返回 `ANSWER_INVALID`。
- **未实测**：真人在手机上点选；Safari、Firefox、微信内置浏览器。点击行为规则（读题至少 400 毫秒、点击间隔至少 150 毫秒、间隔不能完全相等、鼠标点击间要有移动）是按经验定的，需要真实流量校准。
